# Domain documentation

Read the [glossary](../../CONTEXT.md) before design, implementation, or review, then use its terms consistently. Consult the [ADR index](../adr/README.md) and read decisions relevant to the change.

Keep definitions in the glossary and architectural rationale in numbered ADRs. When a change conflicts with an accepted decision, identify the conflict and resolve it explicitly; record an agreed replacement in a superseding ADR.

Use the [documentation index](../README.md) to find the applicable requirements and acceptance criteria. ADR acceptance records a design decision; implementation claims require observed behavior and verification evidence.
